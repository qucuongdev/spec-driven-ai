# Coding Agent Entry Point

The portable AI-DLC kit lives in `.aidlc/`; work from the project root.
Give one Jira ticket; the bundled company workflow targets a reviewed GitHub PR.
1. Read `.aidlc/workflows/ticket-autopilot.md` and `.aidlc/rules/`.
2. For company delivery follow `.aidlc/workflows/jira-to-github.md`.
3. Read `.aidlc/docs/COMPANY_ROLLOUT.md` and effective company policy.
4. Use `.aidlc/context/`; bootstrap missing facts from authorized sources/code.
5. Keep records in `.aidlc/specs/active/TICKET/`; follow the selected profile.
6. Coordinator only: dispatch `.aidlc/agents/` specialists; children never delegate.
7. See `.aidlc/docs/USER_GUIDE.md#multi-agent-collaboration` for harness binding.
8. Cursor, Claude Code, Antigravity and Windsurf use supported agent tools.
Resolve routine gaps yourself; ask only genuine access, policy or business blockers.
Preserve existing work; isolate ticket changes on the correct branch/worktree.
UT from AC/spec before logic: valid red -> coder green -> independent HEAD review.
Agent observations never substitute for human approvals or required GitHub reviews.
Use progress/revise for autonomous work; reviewed/legacy records need real decisions.
PR mode completes only at a real PR URL with required checks/review and no blockers.
Respect existing authorization for branch push/PR/review; never forge APPROVE.
Merge, deployment and Jira writes need separate explicit authorization.
